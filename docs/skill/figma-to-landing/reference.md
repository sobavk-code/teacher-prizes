# figma-to-landing: справочник

## Какие инструменты Figma MCP за что отвечают

| Инструмент | Для чего в этом скиле | Заметки |
|---|---|---|
| `whoami`, `mcp_auth` | проверка входа | при ошибке авторизации сначала `mcp_auth` |
| `create_session` | открыть сессию до первого чтения | `sessionId` передавать во все вызовы |
| `get_metadata` | карта слоёв: id, имя, размер, позиция | ответ может быть 100+ КБ и попадает в файл, читать через `outline.mjs` |
| `get_variable_defs` | токены (цвета, типографика, радиусы, отступы) | нужен **фрейм**; для страницы (canvas) вернёт «nothing selected» |
| `get_design_context` | референс-код, скриншот и ссылки на ассеты секции | вызывать по одной секции; сначала прочитать `figma-design-to-code` |
| `get_screenshot` | PNG узла по временной ссылке (скачать `curl`) | `maxDimension` по умолчанию 1024: для pixel diff ставить ≥ высоты узла |
| `download_assets` | оригиналы картинок и SVG слоёв | максимум 20 на узел, ссылки временные |
| `get_motion_context` | анимации узла (если в `get_metadata` есть `hasMotion="true"`) | использовать, если нужны keyframes |

## Структура результата

```
OUT_DIR/
  index.html
  css/tokens.css, css/main.css
  js/main.js
  assets/ (icons/*.svg, images/*.webp)
  figma/
    outline.json, sections.md
    1728.png, 1440.png, 1024.png, 768.png, 360.png   # полностраничные эталоны
    sections/NN-name.png
  report-figma/   # проверка built↔Figma
  report/         # трёхстороннее сравнение
  REPORT.md
```

## Известные грабли

Пополняй после каждого проекта.

- `node-id` в URL пишется через дефис (`1524-13629`), в вызовах MCP допустимы оба варианта (`1524:13629` и `1524-13629`).
- Узел-страница (тег `canvas` в `get_metadata`) не годится для `get_variable_defs` и `get_screenshot`. Нужен конкретный фрейм.
- В макете, как правило, есть и «главный» фрейм, и раздел «Адаптивы» с теми же секциями. Основной брейкпоинт берём из «главного», остальные из «Адаптивов». Проверь, что высоты секций совпадают, иначе секции отличаются между разделами.
- Слои с одинаковыми названиями в разных брейкпоинтах (`Hero block`, `FAQ`, `Banner`) не одно и то же: у каждого свой `nodeId`.
- Декоративные картинки собраны из десятков эллипсов и векторов. Верстать их как HTML нельзя. Экспортируй узел целиком (`download_assets`, png ×2) и подставляй как `<img>` или `background-image`.
- Фон баннера часто шире экрана (например, 1800 при ширине 1440). Это не ошибка: он обрезается контейнером, ставь `overflow: hidden` и `object-fit: cover`.
- `Blur` (background blur 32) воспроизводится через `backdrop-filter: blur(32px)`. Проверь, что у родителя есть фон, иначе эффекта не будет видно.
- Названия слоёв смешаны (русские и английские). Для CSS-классов и `id` дай свои, латиницей: `hero`, `presents`, `functions`, `how-to`, `block-8`, `faq`, `banner`, `footer`.
- Скриншот `get_screenshot` с `maxDimension` 1024 слишком мелкий: полоса diff будет «шуметь». Всегда ставь `maxDimension` ≥ высоты фрейма.
- Анимации и lazy-load: `compare.mjs` замораживает CSS-анимации и прокручивает страницу до конца. Но если вёрстка скрывает блоки до появления через JS, перед снимком они должны быть видимы.
- Reference может иметь куки-баннер, чат-виджет или другую шапку. Это шум в diff, а не ошибка built. Укажи в отчёте.

### Грабли из проекта «Лендинг розыгрыша» (Ассистент преподавателя)

Figma MCP:
- Вызывай инструменты Figma строго по одному. Параллельные вызовы обрываются («operation was aborted»).
- Лимит Figma считается по месту (seat). У View-места на Pro он кончается быстро. При ошибке лимита повтори один раз, затем остановись и сообщи человеку, не перебирай варианты.
- `get_variable_defs` требует узел-фрейм, на странице (canvas) отвечает «nothing selected».
- `get_screenshot` возвращает короткоживущую ссылку: скачивай сразу. Выше 1x не увеличивает, поэтому для ×2 используй `download_assets` с `defaultScale: 2`.
- `download_assets`: максимум 20 растров и 20 SVG на узел, узлы внутри экземпляров компонентов (id вида `I…;…`) не экспортируются и отдают пустой результат. Иллюстрации карточек вырезай кропом из ×2-экспорта родительского узла (Python/PIL), координаты считай из размеров карточек и отступов.
- Экспорт слоя-рисунка с холста (canvas) даёт непрозрачный тёмный фон `#1e1e1e`. Для картинок бери экспорт целого блока секции.
- Узел фона баннера (`img_footer`) на скриншоте отдаёт только фон без объектов. Если объекты нужны, а текст мешает, кропни область баннера из полностраничного PNG и залей область текста фоном из `img_footer`.
- `get_design_context` для экземпляров может отдать внутренности десктопного компонента (например, ряд шириной 1200 внутри мобильного блока). Истиной служит полностраничный скриншот: сверяй с ним.
- Текст в макете часто содержит ручные переносы строк, которых нет в коде из `get_design_context`. Сверяй переносы по скриншоту и добавляй их как `<br class="m">` (виден только на нужном брейкпоинте), обязательно с пробелом перед `<br>`, иначе на других ширинах слова слипнутся.

Вёрстка:
- `<picture>` внутри flex-контейнера с `gap` становится элементом потока и сдвигает соседей. Для фоновых картинок делай `picture { position:absolute; inset:0; display:block }`, не `display: contents`.
- Шапка и блоки с фиксированной высотой внутри flex-колонки сжимаются (`flex-shrink`), если контент переполняет контейнер. Ставь `flex: none` и `justify-content: flex-start` вместо `flex-end`, иначе контент уезжает вверх.
- Класс для `<img>` в `<picture>` собирай осторожно: ошибка в скрипте подстановки дала `class="fn-card__imgNone"` и сломала размеры. После массовых правок HTML сразу запускай `compare.mjs`.
- Горизонтальная прокрутка внутри секции (даты на 360) допустима: дай блоку `overflow-x:auto`, внутри `max-content`, а на `html/body` оставь `overflow-x: clip`, чтобы страница не скроллилась вбок.
- Декор, привязанный к краям фрейма 1728, на более широких экранах привязывай к центру (`left: calc(50% - Npx)`), иначе он «уезжает» к краю окна.
- Отступы контента по сетке `(100% − 1200px) / 2` задавай переменной: `--side: max(120px, calc((100% - 1200px) / 2))`.
- Узкая колонка текста в карточках (FAQ) на границе в 1px переносит слова иначе, чем Figma. Если перенос расходится в одном месте, правь переносом в тексте, а не шириной всех карточек.

Проверка:
- Инструмент чтения изображений может кешировать по имени файла. Для новой версии картинки используй новое имя файла.
- `compare.mjs` показывает `requestfailed` для мобильных картинок, когда ширина окна меняется между прогонами. Это прерванные запросы, не битые файлы, смотри колонку «битые img».
- Прогоняй `compare.mjs` после каждой крупной правки на двух крайних ширинах: ошибка в общем CSS часто ломает другую ширину (десктоп после мобильных правок упал с 1.4% до 3%).
- Публикация (`publish-app`) работает только из запуска, привязанного к репозиторию. В запуске без репозитория коммит и push в локальный репозиторий не помогают. Интеграция GitHub может не уметь создавать репозитории и включать Pages: репозиторий создаёт человек, Pages включается в Settings → Pages.

## Как запускать проверки вручную

```bash
# только структура макета
node scripts/outline.mjs <metadata.txt> --depth 3

# built против Figma
node scripts/compare.mjs --built http://localhost:4173 --figma-dir figma --widths 1728,360 --out report-figma

# три стороны
node scripts/compare.mjs --built http://localhost:4173 --reference https://old.example.com \
  --figma-dir figma --widths 1728,1440,1024,768,360 --out report
```

Коды выхода `compare.mjs`: `0` — PASS, `2` — FAIL (diff выше порога, пропавший текст, горизонтальный скролл, не один `h1` или битые картинки).
