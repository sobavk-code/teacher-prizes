# Промпт для запуска

Положите папку `figma-to-landing` в `.cursor/skills/` проекта (или в `~/.cursor/skills/`, чтобы скил был доступен везде). Подключите Figma MCP. Откройте новый чат в режиме **Agent** и отправьте:

## Короткая версия (скил подхватится сам)

```
Используй скил figma-to-landing.

FIGMA_URL: <ссылка на макет в Figma>
REFERENCE_URL: <ссылка на готовый лендинг, сделанный вручную>
```

## Полная версия (если скил не подхватился или нужны уточнения)

```
Прочитай и выполни скил .cursor/skills/figma-to-landing/SKILL.md.

Задача: по макету Figma через Figma MCP создать лендинг, затем сравнить его
с уже существующим лендингом, сделанным вручную, и выдать отчёт.

FIGMA_URL: <ссылка на макет>
REFERENCE_URL: <ссылка на существующий лендинг>
Стек: статика (HTML + CSS-переменные + vanilla JS)   # или: Next.js + Tailwind
Папка результата: ./landing-<название>

Условия:
- Работай автономно по фазам 0–8 скила, не задавай уточняющих вопросов.
- До фазы 7 не открывай REFERENCE_URL (слепая сборка).
- Макет Figma — источник истины. Эталонный лендинг нужен только для сравнения.
- Если Figma MCP не подключён или нет доступа к файлу, остановись и скажи, что нужно сделать.

В конце дай: ссылку на запуск, таблицу diff по ширинам, вердикт PASS/FAIL,
список остаточных расхождений и список мест, где ручная версия отличается от макета.
```

## Какую модель выбрать
- Модель с хорошим зрением и длинным контекстом: Claude Opus или Sonnet последнего поколения, либо сопоставимая по классу.
- Opus берите для сложных страниц (много иллюстраций, анимации), Sonnet хватает для типовых.
- Режим Agent с доступом к терминалу. Браузерные проверки скил делает сам через Playwright.
